F.R.O.G. 0.44.0 — Area Watch pump readiness summary

Open County Watch, sign in and load FMFCD, then choose Pump readiness.
The shortcut focuses the private summary. Select a pump name to focus its
point on the map and open its evidence / existing readiness form.

The summary shows:
- Backup power needed: current owner report explicitly says Unavailable.
- Refueling requested: current owner report explicitly says Refuel needed.
- Follow-up / unknown: missing, expired or conflicting confirmation;
  unknown backup / connection / fuel / runtime; zero runtime; an outdated
  inventory match; or a retained utility-area concern.
- Responsible work contact, qualified as last reported when overdue.
- Runtime in hours, next readiness review, pump-specific WPC polygon label,
  and the published 72-hour rainfall accumulation window. Expand the rainfall
  dates for exact local hours; source issue / retrieval times remain available.

Counts refer to loaded existing pump records, not verified physical sites.
Categories overlap. Proposed / future assets are excluded. Search and
category filters do not change countywide counts or notification counts.
Missing confirmations are included even without a current utility / rain
overlap; they remain information gaps, not a new hazard classification.

Review order is explicit: utility / rainfall overlap first; then current
resource reports with forecast precipitation, other resource reports, and
remaining review items. Earlier owner review deadlines appear first within
each group. No risk score, runtime adequacy inference or dispatch is created.
Rainfall window dates are accumulation intervals, not storm onset / peak
timing. Blank or uncovered rainfall is unknown, never zero.

A form update immediately refreshes the submitter's summary / banner after
receipt. Other open authorized apps use the existing one-minute readiness
query. A complete confirmation clears only the relevant readiness gap;
utility follow-up remains distinct. Queries are not guaranteed delivery.

Privacy / source integrity
The existing private exercise checklist views and author tracking are reused.
No AGOL items, privileges, sharing or memberships change. Source ObjectIDs
are not permanent asset IDs. Exact code / point / source association changes
require rematching; an unmatched-association count remains visible without
transferring its contact or readiness to another pump. Source failures / stale
readiness checks hide current need totals and contacts rather than showing
zero requests. Disconnect / sign-out clears summary rows from memory.
No private feature or contact is written to GitHub or browser persistence.
