Observed feed repair
Pine Flat supplied one-digit morning hours (for example 2026-10-18 5:00).
The old strict parser rejected those hours, making readings appear stale.
Normalize year/month/day/hour fields with calendar validation and fixed PST.
Identical readings deduplicate at normalized station/sensor/duration/time.
Conflicting readings quarantine only that timestamp as unknown; never pick an
arbitrary value or freeze every metric. Quality counts remain in the snapshot.
Millerton daily requests end at the previous completed source-calendar day.
An earlier published Millerton conflict was not present in the current source
sample; regression fixtures explicitly test recurring conflicts and recovery.

Schedule contract
Sensor 7, event duration E, units CFS, operator-reported scheduled release.
31-day lookback; retain future effective times through the next seven days.
JSON effective times use fixed PST, converted to America/Los_Angeles in UI.
Checked against notice-page examples: MIL 2026-10-16 13:00 PST = 14:00 PDT;
PNF 2026-10-05 04:00 PST = 05:00 PDT. Do not parse HTML page wall times as JSON.
Issuance/revision time is absent; show it as not supplied, never fetch time.
Compare to preceding valid scheduled amount, never to measured total outflow.
Upcoming changes and newly effective changes in the past 24 hours invite
review, including decreases and unknown baselines. Unchanged repeats do not.
Source flags/conflicts and overdue checks suppress cues while preserving
dated evidence. Empty/removed notices do not prove no change or cancellation.
An effective time is at the reservoir, not downstream arrival.
MIL is associated only with Friant-Mendota; PNF only with Kings below Pine Flat.
Stable notice IDs use station and effective time. Content and comparison
revisions, plus transition to effective, require fresh private EOC review.
No automatic activation, dispatch or unattended notification is implemented.

Refresh and recovery
The existing GitHub Actions job targets 15 minutes, subject to GitHub delays.
Four bounded CDEC requests per run: observations and schedules per station.
The app polls the published snapshot each visible minute; 45-minute collector
and seven-minute app-check freshness gates remain in force. Measurement age
is separate. Failed observations and schedules retain their own success time.
CI retrieves the last published public snapshot before collecting, so a clean
checkout does not replace recent retained evidence with an old repository seed.
Local preview runs the existing --watch collector with --use-system-ca.
Inspect Actions collection output for station errors, notice errors, counts
and conflicts; use publisher links and coordinate with USBR/USACE during gaps.
No complete notice-revision archive; approved private briefings remain the
separate snapshot/handoff workflow. Maintainer and backup still need assignment.
