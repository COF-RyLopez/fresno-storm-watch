1. AGOL administrator: enable the two Notebook privileges

For the existing owner account, confirm an eligible user type and a custom role containing Content → Create and edit notebooks and Content → Schedule notebooks. Retain the existing content/publishing privileges; a full Administrator role is not required for this design. Keep the Notebook private and select Standard rather than an Advanced/GPU runtime. Record the selected runtime version before acceptance. Esri privilege reference.

Approve the schedule and credit allowance before activation. Esri lists Standard scheduled compute at 1.5 credits per runtime hour, calculated per minute, with a 30-credit minimum balance when budgeting is enabled. For planning, 24 daily runs at five billed minutes each would use about 90 credits over 30 days, plus feature/file storage. Actual use depends on measured billed runtime; this is an estimate, not a hard spending cap. Current credit rates.

Approve a dedicated identity, for example FROG_FMFCD_READER, with read-only access to the county FMFCD service. This name is a suggestion; no account has been created. Assign credential rotation and failure-monitoring ownership. The collector reads only pump layer 0 and never edits this service.

In county AGOL, as the inventory owner, choose Content → New item → URL, enter the FMFCD MapServer service root, and use Esri's Store credentials with service item option with the approved identity. Enter credentials only in that official setup dialog. Name the connection F.R.O.G. FMFCD pump collector source — PRIVATE. Keep it owner-only, with no group, organization or public sharing. An approved stored-credential connection should expose a protected https://utility.arcgis.com/usrsvcs/…/MapServer URL. Esri connection instructions.

Confirm that county authentication, certificates and network rules support this connection and a read from the AGOL runtime. If the stored-credential option is unavailable or the authenticated cloud read fails, stop and have GIS/IT arrange an approved county-managed runner and credential store. The credential-free template is also available for review. Its default ENABLE_REFRESH = False makes Run All report activation pending without reading or changing live data.

  1. Set SOURCE_ITEM_ID to the owner-private connection's item ID and APPROVED_PROXY_URL to its exact protected proxy URL. These identify the connection; credentials stay in Esri's secured item.

4. GIS maintainer: create one hourly task

  1. Save the private Notebook with the approved Standard runtime.
  2. Open Tasks → Create task. Name it F.R.O.G. FMFCD pump inventory — hourly.
  3. Add the task parameter RUN_CONTEXT with the string value scheduled. Leave the saved Notebook's default context manual; only an actual scheduled invocation reports automatic checks.
  4. Choose an hourly repeat with interval 1. Set maximum runtime to 5 minutes, leave Use workspace off, and leave saving injected parameters back to the Notebook off. No private feature files are required.
  5. Create the task only after credential/access tests and credit approval. Verify at least two successful scheduled executions and the form's source-check time advancing while the browser is closed.

AGOL task starts are approximate, and a running prior execution causes another run to be skipped. Do not create a second task or use manual copying while the schedule is active. Scheduling and task behavior.

5. Operations: detect failures and preserve the working copy

Assign a named GIS/IT monitor and an approved failure-notification route before operational acceptance. Review task failures, skipped runs and credit consumption. AGOL stops a task after five failures. The worker records only counts, duration and safe diagnostic codes; it never logs source features or credentials. Failed uploads leave the last verified view active. Lost responses are reconciled using stable generation IDs and row keys before another upload.

The form distinguishes the snapshot capture date, latest successful FMFCD verification, and AGOL retrieval time. A failed check does not advance success time. With the hourly schedule enabled, three hours without a successful verification blocks new readiness submissions; last-known inventory is not proof of current readiness. Unchanged pump identity/location preserves an open draft during a background AGOL check; changed or removed identity clears selection and requires verification.

Readiness confirmations, fuel/runtime, contacts, assignments and briefing history remain in their existing private stores. Copying inventory does not confirm that a pump runs or has backup power.

Recovery

Pause the scheduled task before using manual maintenance. To release its writer ownership, the owner can run the following in the private Notebook after confirming the task is paused; this changes only refresh metadata, not pump or readiness records:

from arcgis.gis import GIS
view = GIS("home").content.get("20f479bb3708429d84bb8ab5a217e269")
data = view.get_data() or {}
data["frogPumpRefresh"]["enabled"] = False
view.update(data=data)

Manual maintenance then performs a verified source read and reconciles metadata for its new copy. After repairing the source connection or scheduler, repeat the live verification and two scheduled-run checks before resuming acceptance. Keep old snapshots private; retention or deletion requires a separate county policy. Redeploying the preceding app release rolls back the interface without deleting data.
