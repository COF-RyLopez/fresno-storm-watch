First ArcGIS Pro preparation pass

  1. Pick two small pilot reaches. Begin near the Hwy 41 San Joaquin crossing and near Pine Flat/Kings River. Draw an AOI that includes approaches and connected upstream/downstream terrain. Download only intersecting tiles plus a margin; avoid a county-wide point-cloud download initially.
  2. Keep original data and metadata. Save the DEM, tile index and metadata separately from derived outputs. Record acquisition dates, horizontal CRS, vertical datum, units, geoid and the project accuracy report. Inspect each raster's properties in Pro, even when the index lists a CRS.
  3. Reconcile elevation references before combining sources. The recommended 2021 source uses US survey feet; the 2022 source uses meters. The older Fresno source also uses a different geoid model. Select a common engineering CRS and vertical reference with the model owner. Use an explicit, supported transformation where required. Changing a CRS label with Define Projection does not transform elevations; a feet-to-meters conversion does not perform a vertical datum transformation. Keep a record of every transformation.
  4. Review the existing bare-earth DEM first. Add it to a map, create a hillshade, inspect profiles through levees, bridge approaches and channels, and check voids and tile seams. Keep the original resolution for inspection; a separate 1 m display derivative can be useful after checking terrain detail. Do not describe resampling as improved accuracy.
  5. If needed, build a LAS dataset. Use Create LAS Dataset, compute statistics and confirm the classification, density and withheld/noise handling. Filter to verified ground points (normally class 2). Inspect bridge, levee and canopy sections. With LAS Dataset To Raster, use elevation and floating-point output. Choose a cell size supported by point density and the purpose. Triangulation can honor supplied breaklines; binning does not honor them. Verify licensing for the tool before processing.
  6. Preserve the surveyed terrain. Keep any drainage-conditioned surface separate. Do not automatically fill or breach levees, gates, ponding basins or road embankments. Culvert inverts, submerged-channel bathymetry, bridge openings and post-2023 changes need suitable surveys or operator/engineering records. Gauge stage cannot be subtracted directly from a DEM without datum reconciliation.
  7. Check, then publish a small preview. Compare with appropriate control points and cross-sections, record vertical errors and unresolved gaps, and review with the model owner. Use a tiled elevation service for ArcGIS 3D ground and a raster/hillshade service for display. Point cloud scene-layer content is an option for inspecting classified points. Confirm hosting privileges and storage costs before publishing.

LiDAR helps describe terrain and infrastructure context. It does not, by itself, provide a flood forecast, current channel capacity, safe access or an approved staging location. HEC-RAS still needs reviewed geometry, boundary conditions, structures, roughness and operating assumptions.

Waterways: GeoParquet is ready for a format trial

A validated extract contains 16,184 named USGS waterway segments intersecting Fresno County. It preserves full geometry, including portions crossing the county boundary, stable id3dhp identifiers and source attributes. It contains rivers, streams and named canals/ditches; unnamed detail remains in the publisher service. The extract is a reference snapshot, not current flow or a complete local channel inventory.

All records survived validation and a write/read round trip; WKB geometry bytes and stable IDs matched. These sizes are not browser-speed measurements. The current map already requests viewport features from USGS, so replacing that with a whole-county file is not automatically faster.

ArcGIS ParquetLayer currently supports the 2D map, WGS84/Web Mercator, and GZIP/Snappy/uncompressed files. It remains beta; it does not replace the existing SceneView waterway source. For an SDK 5.1 trial, explicitly set geometryType: "polyline" and WKB geometry encoding; Esri documents an autodetection issue. Keep source dates as explicitly labeled epoch milliseconds.

Use GeoParquet for reusable feature queries and analysis. For map drawing, the next comparison should measure cold/warm load, bytes, memory, panning and label performance against the current viewport service and a scale-dependent vector tile cache. Keep detailed, stable-ID source features available for queries. LiDAR point clouds are better kept as LAS/LAZ or COPC, and terrain rasters as GeoTIFF/COG or elevation tiles, rather than converted into waterway-style GeoParquet.

The reproducible exporter is scripts/export-waterways.py in the project, with pinned dependencies, a provenance manifest and rejection accounting. The reviewed extract was delivered to the county project workspace. It is not silently substituted for the live map source.
