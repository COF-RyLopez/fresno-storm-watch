# Named lake and reservoir outline search (0.34.0)

Source: USGS 3D Hydrography Program Waterbody layer, https://3dhp.nationalmap.gov/arcgis/rest/services/usgs_3dhp_all/MapServer/60 . This index reuses the October 20, 2026 validated public acquisition recorded in the 0.33.0 water-body manifest. No new network requests or private data are used during this build.

Accounting: 7,118 source features = 417 named Lake-class polygons accepted + 6,554 unnamed Lake-class polygons excluded from name search + 147 other feature-type polygons excluded. The 417 named polygons form 411 identity groups. Grouping uses a matching nonzero GNIS identifier, or an individual source ID if GNIS is absent. Equal names with different identities remain separate results. All original 7,118 features remain in the water-body basemap; unnamed features are not assigned invented searchable names.

Geometry: complete original publisher polygons in WGS84 XY, including holes, disconnected parts and portions beyond Fresno County. No clipping or simplification. Rings use Esri clockwise exterior / counterclockwise hole winding. This can show more of a boundary-crossing lake than the county-envelope-clipped basemap. Geographic bounds describe the full outline, not a dam or label point. Shards load only on selection, keyed by validated public filenames. They contain only public reference geometry.

Aliases: published name variants and identifiers are searchable. Optional leading/trailing “Lake” is omitted as a name-search convenience. The existing Millerton/Friant (MIL) and Pine Flat (PNF) watchlist associations supply their app aliases; selecting those reporting-site search results uses the associated complete lake outline when available. A reporting point remains explicitly labeled if lake-index access fails. Search aliases are not additional publisher names or proof of hydraulic connectivity.

Nearby references use horizontal local-projected metric distance (EPSG:26944, NAD83 / California zone 4) to the complete footprint, including its interior. An intersecting geometry has distance zero. Holes are preserved. The SDK uses its default equation-based WGS84-to-NAD83 transform; this is approximate geographic vicinity, not survey accuracy. Stream and street queries retain their existing geodetic backend. This is geographic vicinity, not routing, predicted flooding, safe access, downstream arrival or an instruction to deploy resources. The existing adjustable 0.5 / 1 / 2 / 5 mile distances and source-status rules remain.

Reproduce: use the pinned requirements-waterways.txt environment to run scripts/build-waterbody-search.py after scripts/acquire-waterbodies-county.py. The build checks exact raw-source, boundary and object-ID inventory hashes before processing. Manifest records the source, accounting and every geometry-shard checksum. Tests verify identity grouping, polygon winding/holes, exact bounds, aliases, full-extent navigation, partial-index failures, privacy invalidation and source accounting. No queries, credentials or private asset features are saved in public files or persistent browser storage.

Reference footprints are not current shorelines, water levels or flood extents. Named county facilities appear only after their authorized layers are loaded; the search grants no access.
